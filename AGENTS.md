# Правила проєкту (AGENTS.md = CLAUDE.md, текст однаковий)

На старті прочитай KB.md і STATE.md.
Проєкт: Python-сервіс «Демо-маркет» у папці support/, контракт у CONTRACT.md.
Бібліотеки, базу й API не додавай без мого підтвердження.
Перед зміною опиши план. Після зміни запусти `uv run pytest -q` і назви 3 перевірки з KB.md.
Наприкінці сесії онови STATE.md: заплановане не пишеться як зроблене.

## Як запускати

- Python запускай тільки через `uv run`: `uv run python -m support.demo`, `uv run pytest -q`. Голий `python` не використовуй.
- На Windows має бути `PYTHONUTF8=1` (`setx PYTHONUTF8 1`, потім новий термінал). Перевірка: `uv run python scripts/doctor.py`.
- За замовчуванням працює mock-режим: без ключа, без мережі, ціна $0. Живий провайдер вмикає тільки людина через `.env`.
- Блок Python з уроку зберігай як `try_<назва>.py` у корені, запускай `uv run python try_<назва>.py`, потім видаляй (`try_*.py` у `.gitignore`).

## Контракт

- Імена, типи й категорії беруться з CONTRACT.md і `support/contract.py`. Не перейменовуй і не змінюй їх без підвищення `CONTRACT_VERSION`.
- Категорії тільки українські зі списку контракту. Гроші тільки в копійках, `int`; `float` для грошей ніколи.
- `customer_id` бере код із сесії, модель його ніколи не заповнює.
- Модель викликається тільки через `call_model` з `support/llm`. Ніяких прямих SDK-викликів у коді уроків.

## Безпека і тести

- Ключі тільки в `.env`, який не потрапляє в git. Ключ ніколи не пишеться в код, у `web/` чи в лог.
- Не редагуй і не видаляй тести, щоб вони пройшли, і не став `skip`. Якщо тест здається хибним, зупинись і скажи мені.
- У `evals/cases.jsonl` і `evals/own.jsonl` жодних персональних даних: тільки вигадані id `c-17`, `DEMO-1042`.
- `evals/cases.jsonl` це еталонний набір курсу, тести читають тільки його. Свої кейси учня живуть у `evals/own.jsonl` (id `own-NN`, тег `own`), у `cases.jsonl` їх не переносиш. FAIL своїх кейсів у `run_evals` коміт не блокують; блокує тільки червоний `uv run pytest -q`.
