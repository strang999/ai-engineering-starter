# Перевір перед комітом

Виконай по черзі. Сам нічого не коміть: наприкінці покажи звіт і чекай мого «так».

1. Тести: `uv run pytest -q`. Якщо є `failed` чи `error`, зупинись і покажи перший FAILED з traceback (читай знизу). Тести читають тільки `evals/cases.jsonl`. Мої кейси в `evals/own.jsonl` (тег `own`) коміт не зупиняють: їхні FAIL у `run_evals` це результат експерименту, просто покажи їх у звіті.
2. Diff: `git status --short` і `git diff`. Познач окремо:
   - зміни поза планом, про який ми домовились;
   - видалені тести, `skip`, `xfail`, змінені очікувані значення в тестах;
   - ключі й секрети: `sk-`, `api_key`, `.env`, токени в коді, у `web/` чи в логах;
   - `float` для грошей, англійські категорії замість контрактних.
3. Три перевірки з `KB.md`: виконай кожну й запиши фактичний результат.
4. Онови `STATE.md`: що зроблено, що перевірено запуском, що тільки прочитано в коді, один наступний крок. Заплановане не пиши як зроблене.
5. Звіт мені: тести (N passed), знахідки з кроку 2, результати 3 перевірок, запропоноване повідомлення коміту одним рядком.
